## 1. Honest assessment

The *physics* is already at or beyond what shipping renderers do: Hillaire 2020 atmosphere with Bodhaine 1999 Rayleigh, ozone/Chappuis, Kopp & Lean irradiance, hero-wavelength dispersion, Tessendorf/Cox–Munk/Pope & Fry water, Beer–Lambert stars, a 2:1-balanced cubed-sphere quadtree with Ulrich (2002) error metric, cited constants everywhere. The *renderer architecture* is a decade behind the hardware it now runs on: one 11,171-line compute megakernel (`shaders/PathTrace.slang`, `main()` at L7670, bounce loop L8279) does ray-gen, inline `RayQuery` traversal (L3620–3629), five software intersection tiers (analytic prims, planet sphere, ocean shell, analytic BVH, SDF/fractal sphere-trace), every BSDF, NEE, ReSTIR candidate generation, the cloud march, the atmosphere march and accumulation — and because the NVIDIA driver miscompiles the fully-inlined 6.6 MB `main`, it is shipped at **`slangc -O0`** (`cmake/Slang.cmake` L48–67), i.e. un-optimised. Sampling is ReSTIR **DI Phase A only** — Lambert primary hits, analytic `light_prims` only, denoiser-gated (L8762–8896) — which is close to irrelevant for a planet lit by the sun and sky; there is no ReSTIR GI/PT, no radiance cache, no sky importance sampling for the procedural sky. Denoising is in-house SVGF (Schied 2017) plus an OptiX final-frame denoiser over CUDA interop; the real NRD integration is a stub (`VulkanNrdLibDenoiser::Encode` copies input to output). Terrain streaming builds one KHR BLAS per 8192-triangle chunk through `Device::CreateBLAS`, which **blocks on `vkQueueWaitIdle` per build** (`PlanetTerrain.h` L33–48), paced to 2 ms/frame, fed by a ~2 ms/chunk CPU bake on 4 workers — the "second low-res Earth", the holes and the late loads all follow from that pipeline shape, not from the quadtree. Meanwhile the installed driver **616.56 (= 32.0.16.1656) exposes every relevant extension [verified]**: `VK_KHR_ray_tracing_pipeline`, `VK_EXT/NV_ray_tracing_invocation_reorder` (SER, real REORDER mode), `VK_NV_cluster_acceleration_structure` rev 4, `VK_NV_partitioned_acceleration_structure`, `VK_NV_cooperative_vector`, `VK_KHR_cooperative_matrix`, `VK_EXT_shader_float8`, `VK_KHR_ray_tracing_position_fetch` — and the engine enables none of them (`VulkanDevice.cpp` L1033–1082 requests swapchain, deferred host ops, accel struct, ray query, mutable descriptor type, external memory/semaphore for OptiX; `apiVersion` is still 1.3 at L815; the `Vulkan13Features` struct at L1119 is chained empty). The gap is architectural, and it is exactly the gap Blackwell's hardware (SER, cluster intersection/decompression engines, FP8 tensor cores) was built to close.

## 3. Sequenced roadmap (with acceptance criteria)

The order is dictated by dependencies, not by glamour: (1) unlocks optimised shaders, SER and cluster IDs; (2) is what the repo exists for and needs (1) for ClusterID + coherent shading; sampling/denoising sit on top of a stable frame graph.

### Step 0 — Bookkeeping (S, 2 d)
- Raise `ai.apiVersion` to `VK_API_VERSION_1_4` (`VulkanDevice.cpp` L815); query and log `VkPhysicalDeviceClusterAccelerationStructurePropertiesNV`, `...RayTracingInvocationReorderPropertiesEXT`, `...CooperativeVectorPropertiesNV`; add the `Vulkan13/14Features` we actually need (`synchronization2`, `maintenance4`, `shaderSubgroupUniformControlFlow`).
- **File the driver bug with NVIDIA** (dev forum / NVBug): the `-O2` `PathTrace.spv` + 16×16 repro from the HANDOFF bisection. Independent of the fix below; it costs an hour and may return a driver fix.
- Land the owed Vulkan golden cell (goldens currently run on Embree/software only).
- *Acceptance:* startup log lists the extension/feature flags; the bug ID is recorded in HANDOFF.md; a Vulkan golden exists.

### Step 1 — Escape the megakernel: RT pipeline + SER (XL)
**1a. Skeleton (5–7 d).** New raygen = today's `main()` body; closest-hit for triangles writes a compact hit record `{instance, primitive, bary, t, clusterID}`; miss writes a flag. Shadow/transmittance rays **stay as `RayQuery` inside raygen** (legal in the raygen stage; inline queries are the right tool for visibility rays). Analytic prims / planet sphere / ocean shell / SDF clusters stay as software tests in raygen, merged with the hit record by `t`. Shared descriptor "god" layout gets RT stage flags; `Frame` UBO + 256 B push constants unchanged.
- *Acceptance:* with a fixed seed, images are bitwise-identical to the compute path on every planet fixture (`tests/goldens`), still at `-O0`; `AccelGpuStallCount` unchanged; per-pass GPU timers (tier 4) show trace-pass time within ±10 % of the compute kernel.

**1b. Split (6–10 d).** Sky/atmosphere (`skyColor`, L6753+) → miss shader; terrain/mesh/ocean material decode → closest-hit or callables; cloud march → callable; BSDF sample/eval per material class → callables; assemble with `VK_KHR_pipeline_library` so each module compiles alone.
- *Acceptance:* `PT_SLANGC_OPT=-O2` builds and renders **without TDR** for 10 minutes at 3840×2160 on the orbit→surface flight; trace-pass time ≤ 0.6× the `-O0` megakernel on `planet_surface` (target; report the measured number either way); `-O0` remains a documented fallback, not the default.

**1c. SER (3–5 d).** `HitObject.TraceRay` → `ReorderThread(hit, hint, bits)` with a 4–6-bit hint {surface kind: terrain/ocean/mesh/SDF/sky, needs-cloud-march, in-water medium} → `Invoke`. Use `HitObject.MakeHit/MakeNop` for software hits so they participate in reordering.
- *Acceptance:* ≥ 20 % reduction in trace+shade pass time on the horizon-heavy fixtures (Khronos range 20–50 %; the vk_gltf_renderer path tracer got 47.8 %); pixel-identical output (SER changes scheduling, not results).

**Fallback** if the RT pipeline stalls (e.g. payload pressure): wavefront compute split per Laine 2013 — the May 2026 arXiv comparison on Vulkan HW-RT measured +16 % from wavefront alone, and it also unlocks `-O2`. Do not do both.

### Step 2 — Mega Geometry terrain (XL, staged; each stage independently shippable)
**2a. Device-side chunk builds (8–10 d).** Tile each 64×64-quad chunk into 8×8-quad tiles = **128 tris / 81 verts** per CLAS (NVIDIA's RT sweet spot; spec limit 256) → 64 CLAS per chunk. Build **cluster templates once** for the tile topologies implied by the 16 `TerrainIndexArena` stitch variants (`BUILD_TRIANGLE_CLUSTER_TEMPLATE`), then per frame: one `vkCmdBuildClusterAccelerationStructureIndirectNV` with `INSTANTIATE_TRIANGLE_CLUSTER` over all newly-resident chunks' tiles (positions from the vertex arena, `ClusterID = chunk_slot*64 + tile`), one with `BUILD_CLUSTERS_BOTTOM_LEVEL` producing one cluster-BLAS per chunk (implicit destinations into a sparse pool, sizes read back for compaction as vk_lod_clusters does). TLAS stays KHR (`UpdateTLASInstances`, already drain-free). Decode terrain hits by ClusterID → tile → vertex payload.
- *Acceptance:* terrain `AccelGpuStallCount` delta = 0 per frame; ≥ 100 chunk builds/frame inside a 2 ms GPU budget (vs ~5–10 today); `ResidencyCover.complete == false` frames in the 180-tick paced flight → 0; `pt_planet_residency` and `pt_planet_terrain` pure-function tests untouched and green; scene digest reproducible.

**2b. Permanent coarse residency = P2 (3–4 d).** Keep levels 0..K of all six faces resident as CLAS forever (pick K so e_L is sub-pixel from the highest supported orbit; K = 4 is 1,536 chunks ≈ 12.6 M tris — CLAS memory ≈ tens of MB), exactly as vk_lod_clusters keeps root groups persistent. The 27.7 km sphere remains as a numerical fallback only.
- *Acceptance:* a debug AOV counting `planet_ground` (backstop) hits reads **0 pixels** over the whole orbit→surface→orbit flight at normal speed; the analytic-body land-cover branch (L3409–3438) is no longer the thing you see from 400 km.

**2c. GPU LOD traversal + request feedback = P1 (5–7 d).** Port the selector's `e_L / d > tau·cone_spread` test to a compute traversal over resident tiles (vk_lod_clusters `traversal_run`), writing (i) the per-frame tile list for the cluster-BLAS build and (ii) a "wanted but not resident" request list the CPU services. Prefetch = run the same traversal a second time with the camera advanced by `v·Δt_lookahead` and the look direction extrapolated; union the requests.
- *Acceptance:* at 340 m/s at 500 m AGL for 60 s, zero frames show a tile coarser than the selector's target within the frustum (instrument as a histogram of level deficit); the request→resident latency is reported in `TerrainStats`.

**2d. GPU fine-level bake (L).** Fractal continuation for levels ≥ 15 evaluated in compute and fed straight into template instantiation (vk_tessellated_clusters pattern); coarse levels keep the CPU bake (they carry rock01/σ² and the reference-slope operator).
- *Acceptance:* fine levels never enter `AsyncChunkBaker`; GPU-vs-CPU bake heights agree to ≤ 1 ulp of the float32 chunk-local grid; goldens move only within the stated tolerance.

### Step 3 — Sampling
3a **Sky CDF + MIS** (S) → *acceptance:* variance (RMSE vs 4096-spp reference) at sun elevation 2° on `planet_surface` drops measurably at 1 spp, zero change at noon.
3b **ReSTIR GI** (M–L) → *acceptance:* ≥ 5× MSE reduction at 1 spp on terrain-indirect pixels vs unidirectional PT (paper range 9.3–166×), unbiased mode matches the reference within noise, bias mode documented; no temporal lag beyond the M cap.
3c **NRC** (L) → *acceptance:* ≤ 3 ms added at 1080p (paper: 2.6 ms) while bounces ≥ 2 terminate into the cache; RMSE vs reference not worse than 3b alone at equal time.
3d **ReSTIR PT Enhanced** (XL) only if 3b/3c leave visible noise on glossy ocean/clearcoat.

### Step 4 — Denoising / reconstruction
4a **DLSS-RR (Streamline, Vulkan)** (M) → *acceptance:* 1-spp planet fixtures visually match the 256-spp accumulated reference (ΔE / SSIM thresholds set from the existing goldens); stars still composited post-RR via `StarsComposite`; no ghosting on the orbital 128 m/frame translation (rotation-only sky motion vectors, L7774, already correct).
4b **NRD RELAX/REBLUR finish** (M) → *acceptance:* deterministic output for the Vulkan golden cell; `r_denoiser nrd_lib` replaces the SVGF alias; OptiX becomes reference-only.

### Step 5 — Atmosphere / clouds / ocean
5a LCL cloud base + occlusion (S); 5b ratio-tracking volumetric integrator (M); 5c Mie aerosol phase LUT (S–M); 5d Bruneton-reference MS test (S); 5e JONSWAP/TMA + Jacobian foam (S–M). *Acceptance:* each has a unit test against the cited formula or reference table (Bruneton LUT, Monahan whitecap fraction), matching the repo's "cited constants, derived tolerances" rule.

## 5. Do NOT do (for a planetary path tracer on one 5090)

1. **PTLAS now.** ~1.4 k chunk instances is nothing for a KHR TLAS; PTLAS pays off at 10⁵+ instances or when per-partition translations are wanted for scatter geometry. Revisit with vegetation.
2. **Displaced Micro-Meshes / `VK_NV_displacement_micromap`.** Deprecated by NVIDIA, SDK archived, extension absent from 616.56. Cluster templates + GPU displacement (item 12) is the replacement.
3. **Opacity micromaps.** No alpha-tested geometry; zero benefit.
4. **Area ReSTIR.** Buys AA/defocus resampling; the engine has no DoF and AA will come from RR/DLSS. Later, if a thin-lens camera appears.
5. **DLSS Frame Generation / MFG on Vulkan now.** Vulkan runs FG in interop mode, Dynamic MFG is D3D12-only, needs Reflex markers and swapchain proxying; generated frames do not help a physics sim that wants true frames. Last item, if ever.
6. **Neural cloud shading (2026) / Prague fitted sky (Wilkie 2021).** Rasterization-based and ground-only respectively; both violate "never rasterize" or "from orbit".
7. **`VK_NV_ray_tracing_motion_blur`.** Terrain is static; mesh motion blur is already ray-origin shifting.
8. **Neural texture compression (RTXNTC).** One MODIS raster and a few PBR tiles — not VRAM-bound; 1.2–1.9 ms decompression cost buys nothing here.
9. **More `-O0`/`spirv-opt` gymnastics as a "fix".** A one-hour probe (Slang `-O0` → `spirv-opt` with a curated pass list minus `--inline-entry-points-exhaustive`) is fine as data; the structural split in Step 1 is the fix.
10. **Investing further in OptiX denoiser or in-house SVGF.** OptiX is a final-frame denoiser reached over CUDA interop; SVGF is 2017. Keep OptiX as an offline reference switch, retire SVGF once NRD/RR land.
11. **A GPU light-tree build.** The CPU build is < 1 ms for 1 k lights and there are no many-light scenes on the planetary path.
12. **Hand-writing a Nanite-style DAG simplifier for terrain.** The cubed-sphere quadtree with `e_L` is already a valid cluster-LOD hierarchy with a cited error metric; use it.
